Design Section 2b: Polymorphic Component Architecture

Every component self-describes its edit form — no hardcoded section types

The Problem with Hardcoded Section Types

❌ Previous Approach (rigid)

// Hardcoded: one form per type
if ($type === 'hero') → show hero fields
if ($type === 'services') → show services fields  
if ($type === 'faq') → show faq fields
// Need code change for every new type!

New component = new code. Doesn't scale.

✅ Polymorphic Approach (dynamic)

// Each component declares its own schema
class HeroComponent implements SectionComponent {
  public function editSchema(): array {
    return [
      Field::text('title')->translatable(),
      Field::image('background'),
      Field::text('cta_text'),
      Field::url('cta_link'),
    ];
  }
}
// Zero code change for new types!

New component = new class. Auto-discovered.

SectionComponent Interface

Each component implements this contract
interface SectionComponent
{
    // Identity
    public function key(): string;          // 'hero', 'cards', 'faq'
    public function label(): array;         // ['ar' => 'القسم الرئيسي', 'en' => 'Hero']
    public function icon(): string;         // 'heroicon-o-sparkles'

    // What does this section contain?
    public function layout(): SectionLayout; // SINGLE (one block) | LIST (repeatable items)

    // Client edit form — Filament form schema
    public function sectionFields(): array;  // Fields for the section header (PostCategory)
    public function itemFields(): array;     // Fields per item (Post) — empty for SINGLE layout

    // Rendering
    public function bladeView(): string;     // 'crm::components.homepage.hero'
    public function toApi(PostCategory $section): array; // JSON for Angular

    // Validation
    public function rules(): array;          // Laravel validation rules
    public function maxItems(): ?int;        // null = unlimited
}

enum SectionLayout { case SINGLE; case LIST; }

Example: How Different Components Define Themselves

🎯 HeroComponent
Layout: SINGLE
Section fields:
- title (translatable text)
- subtitle (translatable text)
- background_image (image)
- cta_text (translatable text)
- cta_url (url)
Item fields: none
⭐ ServicesComponent
Layout: LIST
Section fields:
- title (translatable text)
- subtitle (translatable text)
Item fields:
- title (translatable text)
- icon (icon picker)
- description (translatable textarea)
- image (optional image)
Max items: 12
❓ FaqComponent
Layout: LIST
Section fields:
- title (translatable text)
Item fields:
- question (translatable text)
- answer (translatable richtext)
Max items: unlimited
🆕 Your Future Component
Layout: SINGLE or LIST
Section fields:
- whatever fields you need
- translatable automatically
Item fields:
- your custom fields
- all standard field types available
Just add a class. Zero config.
